## Context

阅读页当前支持整行点击的 L1 逐句注，也支持 L2 赏析返回 `word_notes` 并在原文中显示可点击标记。用户仍无法把自己遇到的字词直接交给 AI 解释；如果改用追问，解释不会与原文位置绑定，也不便于再次查看。

实现必须延续现有约束：LLM 由用户自配并由 APP 直连，个人注本只存本机 SQLite，API Key 不进入数据库或日志；没有 Key 时阅读功能仍可用。现有 `notebook_entries` 表已经能承载结构化 JSON，不需要迁移或新表。

## Goals / Non-Goals

**Goals:**

- 用户可在正文中长按/拖动选择一个字、词或短语。
- 选择菜单提供明确的“AI 解释”操作，并使用现有 `AnnotationService` 和人格配置发起请求。
- 解释请求携带完整诗文、所在行和用户选中文本；结果包含解释与不确定性状态。
- 成功结果保存为本地可编辑注本，并在对应原文位置显示下划线标记。
- 已有自动词语解释和用户解释共存；点击任一标记都展示对应解释。
- 兼容旧的 `EssayContent` 与旧注本 JSON，失败或取消不产生半成品。

**Non-Goals:**

- 不提供权威在线词典或服务端词典接口。
- 不改变原诗文本、SQLite 诗库内容或全文检索索引。
- 不把用户选择内容、解释或注本上传到 Worker/R2。
- 不实现跨设备同步、批量选词或整篇自动预取。

## Decisions

### 1. 使用 Flutter 原生文本选择菜单，而非自绘选词手势

将正文行改为可选择文本，并通过 `contextMenuBuilder` 注入自定义菜单项。这样沿用 iOS/Android 原生的长按、拖动、选区手柄和辅助功能行为，不需要自行处理字符坐标映射。原有 AI 标记仍使用 `TextSpan` 点击识别；进入选择操作时，菜单动作优先于普通行点击。

备选方案：自己在 `GestureDetector` 中计算起止字符。该方案难以兼容多行、字体回退、中文字符边界和系统放大镜，因此不采用。

### 2. 解释请求使用独立的本地缓存条目

每次用户选词生成一个 `NotebookKind.wordNote` 条目，`target` 由正文行号、选中文本和选区起止位置组成并截断到安全长度，再通过现有 `notebookEntryId` 计算稳定 ID。内容 JSON 保存 `term`、`explain`、`line_index`、`start`、`end`、`uncertain` 和 `source=user`。同一位置再次请求时优先读取缓存；用户编辑后遵循现有 `user_edited` 保护规则。

不把用户解释塞进 L2 essay 的 `word_notes` 数组，避免编辑/删除一个用户标记时覆盖整篇赏析，也避免自动赏析重生成时覆盖用户资产。原文渲染层合并 L2 自动词注和独立用户词注。

### 3. 新增结构化结果类型并做原文命中校验

增加 `SelectedWordNote`（或等价领域类型），解析时要求 `term`、`explain`，可选 `line_index`、`start`、`end` 与 `uncertain`。服务端返回的解释必须经过客户端校验：行号有效、选中文本与正文对应区间完全一致；若模型未返回位置，则使用用户请求中的位置补全。无法验证时不落库，并展示可行动错误。

解释请求使用 JSON mode，兼容失败时沿用现有一次重试/普通 JSON 请求策略。Prompt 明确只解释用户选中的原文，不扩展成诗文外事实；不确定时返回 `uncertain=true`，不编造出处。

### 4. 解释面板复用现有词语解释视觉语言

用户生成的标记与自动词注都采用点状下划线；点击后打开同一个解释面板，显示词语、解释、来源标签（“我选的词”）和不确定提示。面板提供“编辑注本”和“重新生成”，编辑后使用现有双重确认逻辑保护手写内容。

### 5. 没有 Key 时不改变阅读路径

“AI 解释”菜单仍可见，点击后打开现有无 Key 引导；选择状态不被清除。网络失败、取消请求或解析失败只显示错误，不创建注本条目。

## Risks / Trade-offs

- [系统菜单在不同 Flutter/OS 版本上的自定义按钮布局不同] → 使用 Flutter 官方 `AdaptiveTextSelectionToolbar` 与 `ContextMenuButtonItem`，并保留复制、全选等默认操作。
- [模型返回的词语位置不可靠] → 请求中传入行号和选区范围，客户端以原文精确匹配校验；校验失败不显示标记。
- [选区包含标点或跨越多行] → 首版允许选择范围，但规范化为单行、非空文本；跨行选择显示“请在同一句中选择”并不请求 AI。
- [同一词语在同一句出现多次] → 以 start/end 位置区分缓存条目，点击标记使用独立范围。
- [用户编辑后重新生成覆盖内容] → 复用现有一次确认/手写内容二次确认机制。

## Migration Plan

1. 继续使用 schema v2 的 `notebook_entries`，仅增加新的 `kind` 值和 JSON 字段，无数据库迁移。
2. 读取旧条目时未知 `kind` 仍安全跳过；旧 `EssayContent` 缺少 `word_notes` 时默认为空数组。
3. 发布后新选择解释逐步写入本地；卸载或清理应用数据时随本地注本一并清除。
4. 若需要回滚，移除选择菜单和新 kind 的读取入口即可，已有条目保留但不影响原有 L1/L2/L3。

## Open Questions

- 首版选择跨行时只提示限制，后续是否支持跨行短语由真实使用反馈决定。
- 是否在注本列表中单独显示“我选的词”类型，首版沿用现有按诗聚合列表并增加图标即可。
