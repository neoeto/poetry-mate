## ADDED Requirements

### Requirement: 用户选择词语发起 AI 解释
阅读页 SHALL 支持用户在同一句正文中选择一个字、词或短语，并从系统文本选择菜单发起“AI 解释”。请求 MUST 通过用户已配置的 LLM，携带全诗正文、所在行和原文选区；没有 API Key 时 SHALL 展示配置引导而不是修改诗文或产生错误堆栈。跨行选择 SHALL 提示用户在同一句中选择，不得发起请求。

#### Scenario: 选择同一句中的词语并请求解释
- **WHEN** 用户长按或拖动选中正文同一句中的“孤”字，并点击“AI 解释”
- **THEN** 应用使用全诗、所在行和“孤”字作为上下文发起一次结构化 LLM 请求

#### Scenario: 无 Key 时选择词语
- **WHEN** 用户选中词语并点击“AI 解释”，但尚未配置 API Key
- **THEN** 应用展示“还没有配置 AI”及设置入口，不写入注本且原文保持不变

#### Scenario: 选择范围跨越两句
- **WHEN** 用户选择范围同时包含两句正文
- **THEN** 应用提示“请在同一句中选择”，不发起 LLM 请求

### Requirement: 用户词语解释本地缓存与原文标记
成功的用户词语解释 SHALL 作为个人注本中的独立条目保存在 APP 本地，并包含原文词语、解释、所在行、选区位置、来源和不确定性状态。应用 MUST 仅在原文精确命中时显示下划线标记；再次打开同一位置 SHALL 优先读取缓存，不重复请求。用户词语解释与 L2 自动词语解释 SHALL 可以同时存在。

#### Scenario: 成功解释后标记原文
- **WHEN** LLM 返回所选词语的有效解释
- **THEN** 应用保存本地注本条目，并在对应原文范围显示可点击的点状下划线

#### Scenario: 再次选择同一位置
- **WHEN** 用户再次选择同一句中相同起止位置的词语并点击“AI 解释”
- **THEN** 应用展示本地缓存解释且不发起新的网络请求

#### Scenario: 模型返回无法匹配原文的词语
- **WHEN** LLM 返回的词语或位置与用户选中的原文不一致
- **THEN** 应用不创建原文标记或半成品注本，并展示可重试的格式/匹配错误

### Requirement: 用户词语解释可查看、编辑和安全重生成
用户点击用户词语标记 SHALL 打开解释面板，展示词语、解释、来源和不确定性提示；该条目 SHALL 支持编辑、删除和重新生成。编辑后重新生成 MUST 先确认覆盖，且手写内容 MUST 经过二次确认后才可覆盖。

#### Scenario: 点击用户词语标记查看解释
- **WHEN** 用户点击原文中带下划线的用户词语
- **THEN** 应用打开解释面板，显示该词语的解释并标明“我选的词”来源

#### Scenario: 编辑后的用户解释受保护
- **WHEN** 用户编辑用户词语解释后点击“重新生成”并取消覆盖确认
- **THEN** 原解释保持不变，不发起覆盖写入

#### Scenario: 不确定性提示
- **WHEN** LLM 将用户词语解释标记为不确定
- **THEN** 解释面板显著展示“仅供参考”类提示
