## MODIFIED Requirements

### Requirement: L2 词语解释与原文联动
整篇赏析 SHALL 可返回若干个诗文中实际出现的词语、对应拼音及解释。拼音 SHOULD 使用结合语境的标准汉语拼音并带声调；解释条目 SHOULD 带有正文零基行号。应用 MUST 仅为正文中精确命中的词语显示下划线提示，点击后展示对应词语、拼音和解释。旧版没有词语解释或拼音字段的赏析缓存仍 SHALL 正常展示。

#### Scenario: 赏析词语在原文中可点击
- **WHEN** 用户完成一首诗的整篇赏析，且结果包含诗文中的词语、拼音和解释
- **THEN** 原文页对应词语显示可点击提示，点击后展示词语、拼音和解释

#### Scenario: 旧缓存缺少拼音
- **WHEN** 已有赏析缓存包含词语和解释但没有 pinyin 字段
- **THEN** 应用正常展示词语和解释，不崩溃、不显示错误读音，并允许后续重新生成补全

#### Scenario: 模型返回诗文外词语
- **WHEN** 赏析结果中的词语不在诗文正文中
- **THEN** 应用不为该词语添加原文标记

### Requirement: 用户选择词语发起 AI 解释
阅读页 SHALL 支持用户在同一句正文中选择一个字、词或短语，并从系统文本选择菜单发起“AI 解释”。请求 MUST 通过用户已配置的 LLM，携带全诗正文、所在行和原文选区；没有 API Key 时 SHALL 展示配置引导而不是修改诗文或产生错误堆栈。跨行选择 SHALL 提示用户在同一句中选择，不得发起请求。用户选词解释结果 SHALL 包含所选词语的拼音（若模型无法可靠判断，字段可为空）。

#### Scenario: 选择同一句中的词语并请求解释
- **WHEN** 用户长按或拖动选中正文同一句中的“孤”字，并点击“AI 解释”
- **THEN** 应用使用全诗、所在行和“孤”字作为上下文发起一次结构化 LLM 请求，并在结果中展示拼音（若返回）

#### Scenario: 无 Key 时选择词语
- **WHEN** 用户选中词语并点击“AI 解释”，但尚未配置 API Key
- **THEN** 应用展示“还没有配置 AI”及设置入口，不写入注本且原文保持不变

#### Scenario: 选择范围跨越两句
- **WHEN** 用户选择范围同时包含两句正文
- **THEN** 应用提示“请在同一句中选择”，不发起 LLM 请求

### Requirement: 用户词语解释本地缓存与原文标记
成功的用户词语解释 SHALL 作为个人注本中的独立条目保存在 APP 本地，并包含原文词语、拼音（可为空）、解释、所在行、选区位置、来源和不确定性状态。应用 MUST 仅在原文精确命中时显示下划线标记；再次打开同一位置 SHALL 优先读取缓存，不重复请求。用户词语解释与 L2 自动词语解释 SHALL 可以同时存在。

#### Scenario: 成功解释后标记原文
- **WHEN** LLM 返回所选词语的有效解释和拼音
- **THEN** 应用保存本地注本条目，并在对应原文范围显示可点击的点状下划线，面板显示拼音

#### Scenario: 再次选择同一位置
- **WHEN** 用户再次选择同一句中相同起止位置的词语并点击“AI 解释”
- **THEN** 应用展示本地缓存解释和拼音且不发起新的网络请求

#### Scenario: 模型返回无法匹配原文的词语
- **WHEN** LLM 返回的词语或位置与用户选中的原文不一致
- **THEN** 应用不创建原文标记或半成品注本，并展示可重试的格式/匹配错误
