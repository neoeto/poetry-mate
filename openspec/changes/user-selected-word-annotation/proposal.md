## Why

当前 AI 赏析只能解释模型主动挑出的词语，用户遇到自己不理解的字词时，仍需要手动提问，且解释不会回写到诗文。增加“选中词语即解释”后，用户可以直接从阅读上下文发起精确解释，并将结果沉淀为本机注本中的可复用标记。

## What Changes

- 在诗词正文中支持长按/拖动选择字词或短语。
- 在系统文本选择菜单中增加“AI 解释”操作；用户确认后调用已配置的 OpenAI 兼容模型。
- AI 请求携带所选词语、所在诗句和全诗上下文，并要求返回简短解释及不确定性提示。
- 将成功解释保存到本地个人注本，之后在原文中为该词语显示可点击标记。
- 点击用户生成的标记时展示解释、来源和不确定性提示；支持编辑、删除和重新生成保护规则。
- 无 API Key、网络错误或模型返回异常时保持可操作的阅读体验，不写入半成品标记。
- 兼容已有 AI 赏析缓存和旧版注本数据。

## Non-goals

- 不实现服务端词典、公共释义库或账号同步。
- 不将选中的原文、解释、API Key 或个人注本上传到 Worker/R2。
- 不改变诗词正文、检索索引或原有 L1/L2/L3 赏析协议。
- 不要求用户先打开整篇赏析才能解释所选词语。
- 不保证模型解释具备权威辞典性质；不确定内容必须明确标记。

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `poem-annotation`: 增加用户选词、AI 解释、本地缓存、原文标记和解释面板要求。

## Impact

- Flutter 阅读页、文本选择菜单、词语解释面板和注本编辑流程。
- `AnnotationService` 增加选词解释请求及本地缓存读写。
- 注本内容 JSON 增加用户选词解释条目；不新增数据库表，继续使用 APP 本地 `notebook_entries`。
- 需要新增领域模型、解析/幻觉校验、UI 与服务测试；不新增第三方依赖。
